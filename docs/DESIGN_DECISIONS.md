# 设计决定记录（2026-11-21）

来源：[Issue #20](https://github.com/RequieMa/dual-faced-world/issues/20)「需要拍板的 5 个机制问题」，
由仓库 owner 拍板。本文记录决定与**对代码/文档的影响**，避免实现和设计再次漂移。

## 1. 「回溯」改为「回放」（M12）

- **决定**：过去的事情发生在**录像带**里，玩家通过检查录像带内容找线索；不做时间回溯。
- **影响**：
  - `integrated_sim` 的「档案回放 + 可拖进度条 + 线索板」是正解方向，继续演进；
  - `LoopManager` 只负责「轮次 / 重开一轮」，**不承担改写过去**；`rewind_to` 的语义按「回到录像带某一时刻重开」
    理解，不是时间旅行；
  - 文档里不再用「时间回溯」描述玩法（契约与 gameplay 文档已统一改称「回放」）。

## 2. 改变真实的人命运的理由（M13）

- **决定**：留到剧情设计之后，代码先不做特殊规则。
- **影响**：不需要为「真实/幻想」两组人写不同的改写规则；`PersonGroup` 只保留身份与表现差异。

## 3. 终章动作段落（二段跳）不保留（M15）

- **决定**：不保留终章的二段跳段落。
- **影响**：
  - `PlayerController.action_enabled` **默认 `false`**（跳跃动作段默认关闭）；
  - `PlayerController` 的 `setup({"action_enabled": true})` 是唯一的显式开启入口；`JumpSection` 仅作为
    底层可选项保留，不再接进任何关卡；
  - 测试 `tests/test_player_controller.gd` 有专门用例锁定「默认关 / 显式开」。

## 4. 烧毁的摄像头不恢复（M16）

- **决定**：因为不是回溯，烧毁即永久失效，没有「回到过去恢复」这回事。
- **影响**：`CameraSession` 的默认策略就是 `burned` 永久；循环重开（`restart_round`）保留烧毁列表。

## 5. 所有具体数值可配置（M17）

- **决定**：先给出可配置 JSON，实际数值等试玩后定。
- **影响**：摄像头停留/冷却走 `resources/data/surveillance.json`（`dwell` / `cooldown`，schema 校验）；
  交互半径、拖拽拾取半径等仍是代码常量，后续如需也按同一模式抽到数据文件。

## 后续待办

- 玩法闭环：把「回放查线索 → 监控引导 → 过载代价 → 重开一轮」接成可玩流程（见 `TODO.md` 工程段）。
- 二段跳段落不做；如果以后要恢复，改 `action_enabled` 默认值并在本文追加决定即可。
