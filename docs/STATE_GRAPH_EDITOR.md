# 状态图编辑器（2D 设计工具）

把「实体 · 状态」「状态切换」「结局」画成一张可拖拽的图，并且能直接改图后写回 JSON。
它不参与正式玩法，只是策划/程序对齐状态机用的工具。

- 场景：`scenes/state_graph_editor.tscn`
- 数据：`resources/data/state_graph.json`
- 逻辑：`scripts/state_graph/state_graph_model.gd`（纯数据，不碰 UI）
- 回归：`tests/test_state_graph.gd`

打开方式（二选一）：

```sh
godot --path . scenes/state_graph_editor.tscn
```

或在 Godot 编辑器里打开 `scenes/state_graph_editor.tscn`，按 `F6` 运行当前场景。

---

## 1. 界面

| 区域 | 内容 |
|---|---|
| 左栏 | 图里所有「实体 · 状态」小块；新建节点输入框；常用模板 |
| 中间 | GraphEdit 画布：状态节点、切换连线、结局节点 |
| 右栏上 | 节点检查器：改实体/状态；选中结局时改名字/色调 |
| 右栏中 | **结局规则**面板：把状态拖进来当条件，填名字/色调后生成结局 |
| 右栏下 | 切换连线：选起点/终点/触发词 → 添加；下方列出所有切换，可删除 |

画布操作：

- **拖动节点**：拖标题栏移动，坐标会随「保存」写进 `pos`。
- **平移**：拖画布空白处；**缩放**：`Ctrl + 滚轮`。
- **适配**：右上角「适配」把整张图缩进画布；「整理布局」按实体分列重排。
- **选中**：点节点；`Ctrl/Shift + 点` 可加选（检查器只显示最后选中的一个）。

## 2. 做一次「敌人巡逻 + 摄像头烧毁 → 成功逃脱」

1. 左栏找到「敌人 · 巡逻」，把状态小块拖到右栏 **结局规则** 面板里（会变成条件）。
   也可以直接拖画布上状态节点标题栏右侧的紫色「拖」按钮。
2. 同样把「摄像头 · 过载烧毁」拖进面板。
   画布上如果已经有结局节点，把状态直接拖到它身上也等于给它加条件。
3. 在「结局名」里填 `成功逃脱`，色调选「成功（win）」。
4. 点「生成结局（2 个条件）」。

画布上会多出一个绿色结局节点，两条紫色→绿色的条件线连到它；右栏「已有结局」里也能看到、
「查看」会选中并滚动到该节点、「删除」会删掉它。

### 其他做法

- **从端口连线**：把状态节点第二行的「作为条件 ▶」端口拖到已有结局节点左侧的「◀ 条件」端口，
  会把该状态追加进这个结局的条件。
- **状态切换**：把 A 节点的「切换 ▶」端口拖到 B 节点的「◀ 切换」，或右栏「切换连线」里选 A/B、
  填触发词（如 `E 拾取磁带`）后点「添加切换」。
- **新增状态**：左栏输入实体/状态 →「添加到画布」；或把「快速新建」里的模板拖到画布；
  或把已有状态小块拖到画布（复制一个同实体/同状态的节点）。
- **改节点**：点中状态节点，右栏改「实体/状态」→「应用状态」；「删除节点」会连带删掉相关切换和
  把它当条件的结局。
- **改结局**：点中结局节点，右栏改名字/色调 →「应用结局」。

## 3. 数据格式

```json
{
  "version": 1,
  "nodes": [
    {
      "id": "enemy_patrol",
      "kind": "state",
      "entity": "敌人",
      "state": "巡逻",
      "label": "敌人 · 巡逻",
      "tone": "neutral",
      "requires": [],
      "pos": [1160, 40]
    },
    {
      "id": "escape",
      "kind": "outcome",
      "entity": "",
      "state": "",
      "label": "成功逃脱",
      "tone": "win",
      "requires": ["enemy_patrol", "cam_burn"],
      "pos": [1720, 320]
    }
  ],
  "edges": [
    { "id": "e_enemy_blind", "from": "enemy_patrol", "to": "enemy_blind", "label": "摄像头过载闪光" }
  ]
}
```

- `kind`：`state`（实体·状态）或 `outcome`（结局）。
- 状态节点的 `requires` 永远为空；结局节点的 `requires` 是状态节点 id 列表（**全部命中**才触发）。
- `tone`：`neutral` / `win` / `fail`，只影响画布颜色，不参与判定。
- `pos`：画布坐标 `[x, y]`，保存时由节点位置写回。
- `edges`：只表示「状态 → 状态」的切换；结局条件不走 edges，走 `requires`。

判定入口是 `StateGraphModel.evaluate(active_ids)`：传入「当前处于哪些状态节点」，返回命中的结局
（条件多的排前面）。返回的每个结局同时带 `requires` 和 `nodes`（同义，方便 UI/测试）。

---

## 4. 约束与行为

- 结局条件只能是 **状态节点**；不能拿另一个结局当条件。
- 同一状态不能重复加入同一结局（`add_requirement` 返回 false）。
- 删除状态节点会：删掉它相关的切换、从所有结局的 `requires` 里移除；如果某个结局因此没有条件，
  该结局一起删除（不会留下“永远不会触发”的空结局）。
- 新增结局至少需要一个状态条件；载入时空条件的结局也会被丢弃。
- 不允许自环（状态不能切到自己）；同一对状态之间只保留一条切换（新增重复会被拒，
  载入外部数据时重复连线会合并）。
- 切换连线的两端都必须是状态节点；结局节点不能当切换端点。
- 载入 JSON 时，坏节点/坏连线会被跳过并写进 `last_errors`，不会半边污染现图。

## 5. 验证

```sh
godot --headless --path . --script tests/test_state_graph.gd
godot --headless --path . --script tests/run_all.gd
```

测试覆盖：模型增删改、结局判定、`requires` 持久化、节点坐标静默更新、编辑器场景装配、
拖放模板到画布、拖状态到结局面板、生成结局、带条件保存/重载。

交互验证建议（手工）：

1. 打开场景，点「适配」确认整张图可见；
2. 拖一个状态到右栏结局面板，生成结局，检查画布多出结局节点和条件线；
3. 拖节点改位置 →「保存」→「重新载入」，确认位置/条件都在；
4. 删除一个作为条件的节点，确认相关结局被一起清掉。

## 6. 已知限制

- 没有撤销/重做；改坏了用「重新载入」。
- 保存写 `res://resources/data/state_graph.json`，是开发期工具行为；导出后的游戏资源是只读的。
- 画布很宽时靠「适配」/拖动/缩放查看；没有自动折叠。
- 结局条件的多选主要靠「拖进面板」；画布上的 `Ctrl+点` 目前只影响检查器，不会批量建结局。
